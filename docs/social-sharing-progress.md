## Implemented contracts and API boundaries

- `lib/sharing/contracts.ts`, `lib/social/contracts.ts`: independent audiences, safe DTOs, revision strings, service interfaces, bounded operations, copy states. List entries have one thumbnail; detail photo/tag cursors are separately resource-scoped; financial series stay bounded. Preserve existing cumulative-acquisition meanings.
- `lib/sharing/server/cursor.ts`: HMAC versioned cursors bind owner, viewer identity/category, resource, normalized search, filters, sort and revision. Decimal bigint revisions and PostgreSQL timestamp precision are preserved. `SHARING_CURSOR_SECRET` requires at least 32 bytes. A cursor never grants access.
- `read-core.ts` reconstructs DTO allowlists, rejects malformed/oversized results, reduces 21 internal rows to 20 public entries and signs continuation. Item details use independently scoped photo/tag cursors. List/detail photo references and profile avatars are authorized and signed only for displayed rows; missing media is omitted, signing failures are generic 503s. Shared style is reconstructed from theme tokens/fonts/radius only when `profile_share_style` is true. Wishlist tokens resolve to an owner id and reuse the same wishlist projection; they are not an extra grant. `viewer.ts` rejects invalid supplied credentials instead of falling back to guest. Guest preview derives owner from the verified session and forces guest SQL permissions.
- Guarded public endpoints: `/api/public/users/[userId]`, `/boxes`, `/boxes/[boxId]/items`, `/items/[itemId]`, `/wishlist`, `/wishlist/[itemId]`, `/api/public/wishlist/[token]`, `/api/wishlist/preview`, `/api/public/media/[kind]/[referenceId]`. Profile avatars/styles are signed/allowlisted when published. The legacy `/api/wishlist/[token]` route is not cut over.
- Guarded sharing GET/PUT `/api/boxes/[boxId]/sharing`: verified actor, bounded 4 KB JSON, cross-origin browser-write rejection, expected revision/count. `SOCIAL_SHARING_EDITS_ENABLED` controls APIs; `NEXT_PUBLIC_SOCIAL_SHARING_EDITS_ENABLED` independently controls item privacy UI.
- Guarded Social mutations/list/inbox routes use `SOCIAL_MUTATIONS_ENABLED`. Incoming/outgoing request cursors/cache keys differ. Successful mutations return `{success, revision, invalidated}`; refetch authoritative lists/profile for relationship state.
- Public/media responses are private/no-store and vary on Cookie/Authorization. No generic raw-record or caller-supplied trusted-actor fallback exists in new adapters.

## Database migration map and invariants

Files below are under `supabase/migrations/`, in this order:

1. `20260907034821_social_sharing_foundation.sql`: private profile/account state/revisions, independent audiences, item Private/detached fields, canonical social tables and private publication/block/friend/audience predicates. New tables revoke client grants and enable RLS. Guest Friends-only NULL behavior is tested.
2. `20260907035318_social_relationship_transactions.sql`: ordered account/pair locks; request/accept/decline/cancel/unfriend/block/unblock; current request/version checks; sender minute/day and pair cooldown limits; deduplicated/resolved notifications. Opposite requests never auto-accept. Canonical pairs use `social_friendships`; legacy table remains for reconciliation.
3. `20260907040208_canonical_public_reads.sql`: service-only context and bounded box/owned-item/wishlist projections. Root grouping precedes LIMIT; private intermediate boxes split roots. Finances are masked in SQL; expected wishlist prices remain independent; hidden targets are omitted. Block/publication/revision rechecked per call.
4. `20260907121052_box_sharing_transactions.sql`: cycle-safe descendant preview and atomic revision/count-checked sharing save. Propagation changes all three box fields, preserves item Private and advances revision.
5. `20260907124728_sharing_box_invariants.sql`: root Private/false/Private defaults, child inheritance, move preservation, same-owner/cycle guards, immutable ownership, sandbox publication denial. Direct authenticated statements lock account before tuples; transition tables advance revision once per affected owner per statement.
6. `20260907125620_wishlist_item_invariants.sql`: item ownership/targets, structural Private preservation, detached saved audience before box deletion, forbidden detached metadata forgery. Broader target moves fail `privacy_conflict` until consent UX exists. Clear Private separately from a structural edit; move plus Private is supported.
7. `20260907131022_sharing_dependent_revisions.sql`: photo/history/tag/link/settings/profile invalidation and authenticated account locks. Private definer helpers pin empty search paths and revoke execution. Trusted multi-owner DML must pre-lock owners in order. Legacy cross-owner tag links are handled for invalidation but still need constraint reconciliation.
8. `20260907132124_social_request_receipts.sql`: durable per-actor request idempotency. Retrying a key after cancel/decline acknowledges without resending; mismatched target returns conflict. Concurrent receipts/notifications are tested.
9. `20260907144600_social_list_reads.sql`: 20-row public adapter pages from 21 SQL rows; nickname/neutral-label search, no private names/email; identity-free block list; stale actions removed; unread cap 100; mark-read and 90-day eligible-history retention. Pending unresolved requests remain. Retention is not scheduled.
10. `20260907160500_media_lifecycle.sql`: immutable registered assets, photo/avatar references, upload/legacy registration, attach, copy leases, canonical reference authorization and transactional GC queue. Leases/references prevent deletion; pending/deleting/deleted objects cannot attach/sign. Owner deletes commit rows before legacy blob cleanup and skip synchronous cleanup of registered assets.
11. `20260907172603_sharing_box_delete.sql`: service-only atomic delete-all or flatten/move-to-root, cycle/ownership checks, detached wishlist preservation and post-commit photo inventory. Nested selected boxes survive CASCADE row-count semantics.
12. `20260907174306_sharing_owner_media_and_ownership.sql`: composite same-owner FKs, owner-only media authorization and scoped legacy registration. Owner media ignores publication, public media does not. Paste child inheritance is SQL-tested. Item move maps privacy conflict to 409.
13. `20260907181159_media_gc_worker_leases.sql`: two-minute fenced GC claims, retry backoff (30s–1h), bounded orphan/expired-lease sweep, account→asset→queue lock order. New `media_complete_gc(asset,token,success)` replaces unfenced finalization (old finalizer execution revoked). Assets remain `deleting` across failures; stale completion cannot finish a new claim. Immutable asset records survive account deletion; registration still checks/locks an existing owner. Schedule is separate from migration.
14. `20260907182513_public_item_details.sql`: service-only collection/wishlist details with independent photo/tag keysets, financial masking, hidden-target omission, same-owner tags, and list `thumbnailReferenceId` for server signing. Wrong surface/owner is `not_found`. Client EXECUTE remains revoked.
15. `20260908093000_public_profile_avatar_style.sql`: context returns `avatarReferenceId` (owner id) only for a ready avatars-bucket asset, and `sharedStyle` only when `profile_share_style` is true. Tokens, provider names, graph overlay and raw avatar URLs stay out of the SQL DTO.
16. `20260908094600_public_wishlist_token.sql`: service-only token→owner alias. A token is not an extra grant; blocked/unpublished owners and unknown tokens are `not_found`. Legacy `/api/wishlist/[token]` remains until T11.

Historical bootstrap caveat: older migrations begin with ALTERs against tables they never create, and replaying them on `schema.sql` duplicates policies/triggers. Native runner loads the schema mirror then the sixteen social migrations; it does not prove a full historical upgrade replay. Update the mirror only after reconciliation/cutover coordination.
